# AGENTS.md — d-OP

## What this repo is

d-OP is a Chrome / Firefox Manifest V3 extension plus an optional Share web service, built as a Bun monorepo. There **is** a build step (WXT for the extension, Astro for the web app) and a real test suite (Vitest + Playwright). Do not hand-edit files under `.output/` or `dist/` — they are generated.

- `apps/extension/` — the WXT extension (TypeScript MV3, Chrome + Firefox).
- `apps/web/` — the Astro + Cloudflare Workers/D1 Share site (`d-op.sasnews.dev`): landing, `/privacy`, `/terms`, `/explore`, `/p/<shareId>` and `/api/v1/playlists`.
- `packages/shared/` — Zod schemas and pure logic shared by extension and web (local model, share model, API contract). No side effects allowed here.
- `tests/e2e/` — Playwright suites (`extension-chromium`, `web-chromium`, `web-firefox` projects).
- `docs/` — architecture, behavior inventory, share and testing references.

The v1 legacy extension (plain JS at repo root, baseline `fc9d7fd`) is documented in `docs/current-extension-behavior.md`. Root `manifest*.json` are legacy; the shipping manifests are generated by `wxt.config.ts`.

## Entrypoints and file roles (apps/extension)

- `entrypoints/background.ts` — MV3 service worker / event page. Owns the storage single-writer, the player window manager, and **all Share API traffic** (management + import handlers).
- `entrypoints/danime-player.content.ts` — isolated-world content script for the player page (`sc_d_pc`). OP/ED enforcement, playlist playback, seek-bar markers, control bar.
- `entrypoints/danime-store.content.ts` — isolated-world script for work/episode-list pages. Per-episode OP/ED menus and chapter fetches.
- `entrypoints/danime-main.ts` — main-world script; the only code that may touch `window.vc`. Bridges commands via `window.postMessage`.
- `entrypoints/danime-isolated-runtime.ts` — installs the isolated-side bridge.
- `entrypoints/share-site.content.ts` — content script on `d-op.sasnews.dev/p/*` that relays the web "open in d-OP" button into the extension. No `externally_connectable`.
- `entrypoints/popup/`, `entrypoints/options/` — toolbar popup and the privileged management page (playlists, share dialog, consent section, import/export).
- `entrypoints/import/` — extension-owned confirmation window for importing a shared playlist.
- `src/adapter/` — d-Anime page/player boundary (the `window.vc` bridge).
- `src/player/` — player UI, orchestrator, modal host, window manager.
- `src/storage/` — canonical state repository, mutations, migrations, message handling. `dop_v2_state` is the single canonical key; `dop_v2_transient` holds playback pointers.
- `src/share/` — Share client/handler/consent layer. `api-client.ts` (public GET), `management-client.ts` (POST/PATCH/DELETE), `import-handler.ts`, `management-handler.ts`, `consent.ts`, `import-notify.ts`.
- `src/ui/` — options-page controllers (playlists, share dialog, consent section, detached management list).

## Privacy and Share invariants (permanent)

These are product requirements, not implementation details — do not weaken them:

- **Ordinary use is local-only.** No telemetry, no analytics, no cookies, no accounts, no automatic sync. Nothing leaves the browser during normal playlist/playback work.
- **All Share traffic is consent-gated.** `src/share/consent.ts::effectiveShareConsent` is the single gate. Undecided (no record) and declined both block. Every background Share path re-checks consent immediately before fetching.
- **Consent is explicit and revocable.** Grant/decline/revoke only via privileged extension surfaces (options, import confirmation). Writes go through `set-share-consent` — the revision-checked single writer. Revocation blocks future traffic but never auto-deletes remote publications.
- **Whitelisted payloads only.** Publish bodies are the `SharedPlaylist` projection; the manage secret travels only in the `Authorization` header; the import notification is exactly `{eventId}`. Never put secrets, local IDs, or page URLs in Share request bodies or paths.
- **Management requests are options-only.** `management-handler.ts` rejects any non-options sender with `forbidden` — before and regardless of consent.
- **Firefox native consent.** `wxt.config.ts` declares `data_collection_permissions.required=["none"]` plus the optional categories in `SHARE_DATA_COLLECTION_PERMISSIONS`. Keep both lists in sync. A revoked category must fail closed.
- **No remote code, ever.** Everything the extension runs ships inside the package.
- **Never log or render secrets.** `manageSecret`, `sentSnapshot`, `acknowledgedHash` exist only in the vault projection — no UI, no logs, no exports, no docs with real values.

## Architecture constraints you will break if you are not careful

- **Never access `window.vc` from isolated/content code.** The player object lives in the main world (`danime-main.ts`); use the `postMessage` bridge in `src/adapter/`.
- **Chapters are not labeled by d-Anime.** `ws010105Data.chapters[].type === 'none'` marks skippable sections; names are guessed heuristically (duration ~1:30 + position). See `docs/danime-player-contract.md`.
- **Two navigation systems**: work-page OP/ED menus (op-ed mode flag) vs playlist playback (`{ playlistId, index }` + URL params). Playlist mode hides native prev/next; op-ed mode must leave them visible.
- **Single-writer storage.** Pages never touch `browser.storage` directly for canonical state — they go through `UiStorageClient`/`runMutation` so every write is revision-checked.
- **Do not use browser `alert`/`confirm`/`prompt`.** Use the shared modal host (`src/player/modal.ts`).
- Keep injected UI aligned with the native 50 px d-Anime control bar, and never leave orphaned DOM nodes after mode changes.

## How to verify changes

- `bun install` once, then:
- `bun run test:unit` — Vitest unit suite (extension + shared).
- `bun run test:worker` — Miniflare/D1 tests for the Share API.
- `bun run test:e2e` — Playwright (fixture server + built extension/web output). Example: `bun run test:e2e -- --project=extension-chromium privacy-consent.spec.ts`.
- `bun run typecheck` — root tsc, extension `wxt prepare` + tsc, web `astro check` + `wrangler types`.
- `bun run lint` — Biome.
- `bun run check:test-origins` — guards against real origins in tests/fixtures.
- Manual: `bun run dev:extension` / `dev:extension:firefox`, or load `apps/extension/.output/chrome-mv3` after `bunx wxt build`. See `docs/testing.md`.

## Style and conventions

- TypeScript everywhere; Biome is the formatter/linter (`bunx biome check .`). Match existing code style.
- All external input is validated with the Zod schemas in `packages/shared` — parse at the boundary, never trust shapes.
- Keep fetch behavior explicit: `credentials: "omit"`, `redirect: "error"`, `cache: "no-store"`, bounded bodies, timeouts.
