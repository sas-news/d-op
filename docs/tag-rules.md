# d-OP 公開タグルール（システム統一仕様・確定版）

ユーザーへの強制はなし。システム側の「候補提案」が従う canonical taxonomy と命名規則。
バリデーションは既存どおり Zod でバウンダリ検証（ShareTagSchema: NFC・空白圧縮・小文字化・ソート・最大10個・各24文字）。

## 1. 分類軸（canonical taxonomy）

| 軸 | 形式 | 例 | 自動ソース | 備考 |
|---|---|---|---|---|
| OP/ED区分 | enum | `op` / `ed` / `oped` | ローカル導出 | playlist全itemがEDなら `ed`、OPなら `op`、混在は `oped` |
| 対象層 | enum（直接マップのみ） | `キッズ` `少年` `少女` `青年` `女性` | Jikan/AniList demographics | 合成ルールなし。マップに無いものは付けない |
| 放送局 | 系列統一名 | `テレビ東京` `テレビ朝日` | しょぼいカレンダー FirstCh → 正規化辞書 | 地方局名は系列に畳む（ABCテレビ→テレビ朝日）。複数局は複数タグ |
| 年代 | `{YYYY}年` | `2006年` | しょぼカル FirstYear / AniList seasonYear | 初回放送年のみ・1作品1つ |
| シリーズ | 作品群共通名 | `プリキュア` | 複数作品playlistの共通表記抽出 | 装飾記号（☆♪！等）を剥がして最長共通部分 |
| 制作スタジオ | canonical短形（辞書に無ければ取得名そのまま） | `東映アニメ` `京都アニメ` | AniList studios をアニメ制作のみフィルタ→短形辞書 | 放送局・音楽会社・producersは除外 |
| 原作媒体 | enum | `漫画原作` `ラノベ原作` `ゲーム原作` `オリジナル` | AniList source | |
| 掲載誌 | canonical誌名 | `週刊少年ジャンプ` | Wikidata / 手動辞書 | 取れる時だけ付ける。無ければ無し |
| ジャンル | canonical和名 | `魔法少女` `ロボット` `異世界` | AniList genres → 和名マップ | 英語genreを日本語化。マップに無いgenreは付けない |
| アーティスト | 歌手名 | `LiSA` | range.name の「(歌手)」抽出 | 任意・数が多くなりがち |
| 主観系 | ユーザー自由 | `名曲` | 自動提案しない | 既存自由タグとして通す |

## 2. 命名規則

- **放送局**：canonical セットは系列統一名 — テレビ東京/テレビ朝日/TBS/フジテレビ/日本テレビ/NHK/TOKYO MX/AT-X/BS11/WOWOW/キッズステーション 等。「ABCテレビ、テレビ朝日」→ `テレビ朝日`
- **スタジオ**：短形辞書で統一（Toei Animation → `東映アニメ`、Kyoto Animation → `京都アニメ`、ufotable → `ufotable` 等）。辞書に無いスタジオはAPI取得名そのまま付ける（短形が取れないなら長いままOK・落とさない）
- **年**：`YYYY年` 固定、初回放送年のみ
- **言語**：日本語タグ基本。`op`/`ed`/`oped` は英小字
- **上限10個**：優先度順に採用 → `op/ed` → 層 → 放送局 → 年 → シリーズ → スタジオ → 原作 → 掲載誌 → ジャンル → アーティスト

## 3. 複数作品プレイリストのルール

- **intersection ルール**：全作品に共通するタグのみ提案（年がバラバラのプリキュア集→年タグ無し、局/層/スタジオが共通→付く。本番の「プリキュア3DCGエンディング」のタグと同じ結果が自然に出る）
- 単一作品playlistは全軸を提案
- シリーズ横断は共通表記から `プリキュア` のようなシリーズタグを追加

## 4. 提案UX

- シェアダイアログに「候補」ボタン → 提案タグをプリフィル（ユーザーは削除・追加可）。無断では付けない
- タイトルマッチの信頼度が低い作品はスキップして警告表示（誤タグ防止）
- ユーザー自由タグとの混在OK（canonical 以外もそのまま通す）

## 5. 実装の置き場所

- taxonomy・正規化辞書・ルール合成ロジック → `packages/shared`（純粋関数、side-effectなし縛りに合う）
- 外部API呼び出し（AniList/しょぼカル/Wikidata）→ Worker側 `POST /api/v1/tag-suggestions`（D1キャッシュ、キー不要、CORS問題も吸収）
- 拡張 → 「候補」ボタン＋タグ欄プリフィルのみ
- Jev等のAI分類は使わない（決定的パイプラインで十分）。将来タイトルマッチ失敗時のフォールバック用に provider 差し替え可能な I/F だけ残す
